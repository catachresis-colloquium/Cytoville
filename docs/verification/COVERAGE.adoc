`Code coverage checks require a pull request`. Its workflow, signature and

The owner selected queue-compatible measured coverage, retaining an 80% floor

The first hosted measurement, run 45491027535, correctly failed Rust at

== Measurement contract

The CI workflow measures the exact event's base and candidate SHA on separate
fresh hosted Linux runners. For pull requests these are `base.sha` and
`head.sha`; for the queue they are `merge_group.base_sha` and
`merge_group.head_sha`. It never substitutes a branch name, previous green run,
cached report or percentage typed into configuration.

* Rust: cargo-llvm-cov 0.9.1, Rust 1.99.1 and llvm-tools-preview; all workspace
  members and all targets, locked dependencies, no coverage-only cfg and no
  custom package/path exclusions. The tool's default exclusions for dependencies,
  generated artifacts and standalone tests/examples/benches remain in effect.
  Bevy application code is included. This is LLVM executable
  line coverage, including instrumented test targets; it is not branch coverage
  or a claim that every source line executes on Linux.
  The same immutable harness drives both revisions through UMS packaging,
  plaintext and verified loopback TLS, real Bevy input, save/reload, reconnect
  and settings. Instrumented graphical processes must exit successfully through
  the existing application timer and emit nonempty, process-specific profiles.
  Forced cleanup cannot satisfy this requirement. Reports are exported only
  after every journey and language test succeeds.
* Elixir: OTP 28.3.1, Elixir 1.19.4, the complete `server` test suite and actual
  Rust/Zig worker; exported Erlang cover data. The canonical Proven converter
  maps executable lines to source and supplies LCOV. Generated line zero is
  absent from this format. No application module exclusion is requested.
* Each language must independently meet the floor and regression bound.
  Counts are compared as exact rational numbers. Display rounding cannot turn
  79.999% into a pass, or hide a decline exceeding five points.
* Both measurement jobs must succeed. Missing exports, failed tests, cancelled
  jobs, incorrect SHA/event/run/attempt, empty reports, malformed counts,
  mismatched totals and modified report digests are refused.

Raw reports retain the canonical
`hypatia.proven-coverage.report-meta/1` sidecar. The repository receipt binds
both revisions, scope, attempt and file digests. Artifacts from the current
workflow attempt are retained for fourteen days, including incomplete output
after failures; incomplete output cannot satisfy the judge.

== Canonical source and trust boundary

The collection commands and sidecar convention follow
`hyperpolymath/proven-cicd-and-workflows` at
`d28d73ef10c623b507e98ffddb040268e29b5443`. Its
`scripts/coverdata-to-lcov.exs` is executed directly from that pinned checkout.
Its existing collector is deliberately advisory and can retain reports after
test failures. Cytoville's small adapter uses strict command exits and does
not reinterpret that advisory outcome as a pass.

Hypatia's proven-versus-raw evidence classification remains separate. This
gate replaces the raw coverage threshold, not Hypatia's evidence classifier,
Creusot/Pearlite implementation contracts, Verus scopes or ABI/FFI proofs.
It measures neither Zig nor Idris2 executable coverage; those languages keep
their separate build, conformance and proof obligations. Windows/macOS code,
mutation adequacy and hardware measurements
remain unestablished by these Linux line counts.

The coverage collector and judge are checked out at an immutable policy
revision, independent of candidate source. The organization-required CI
workflow must be advanced to the validated workflow revision before protection
is replaced. Its `CI/gate` requires the coverage judge as well as the existing
immutable required-workflow collector. A PR-editable success with the same
check name is not sufficient evidence of enforcement.

Source builds and tests execute candidate code on disposable hosted runners,
with read-only permissions and no checkout credentials. Digests detect
accidental report substitution; they are not cryptographic attestation of an
adversarial build. Protection depends on the pinned workflow, code review and
the other required checks too.

No activation step is marked complete merely because its code exists.
